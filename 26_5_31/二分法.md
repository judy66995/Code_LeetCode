# 二分法（二分查找）超通俗系统讲解
我给你做一份**最完整、最通俗、嵌入式工程师必背**的二分法总结，你看完就能彻底懂。

# 一、二分法是什么？（大白话）
**二分法 = 每次把范围砍成一半，只保留可能有答案的那一半，直到找到结果。**

就像**猜数字游戏**：
- 范围 1~100，你猜 50
- 大了 → 范围变成 1~49
- 小了 → 范围变成 51~100

**每次砍掉一半，速度超级快！**

---

# 二、二分法的核心特点（必须记住）
1. **必须在有序数据上使用**
   有序数组、有序区间、旋转有序数组都可以。
2. **时间复杂度 O(log n)**
   100万个数，最多找 20 次！
3. **空间复杂度 O(1)**
   只用 left、right、mid 三个变量，不占额外内存。
   → **嵌入式/内核最爱的算法！**

---

# 三、二分法的标准模板（背这个就够）
所有二分题都长这样：

```cpp
int left = 起始位置;
int right = 结束位置;

while (left <= right) {
    int mid = left + (right - left) / 2;  // 防溢出
    
    if (找到目标) {
        return 答案;
    }
    else if (目标在左边) {
        right = mid - 1;
    }
    else {
        left = mid + 1;
    }
}
return 没找到;
```

---

# 四、为什么要写 mid = left + (right-left)/2？
因为：
```
mid = (left + right) / 2
```
如果 left 和 right 很大，会**整数溢出**。

写成：
```
mid = left + (right - left)/2
```
**永远不会溢出！嵌入式写代码必须这样写！**

# 五、二分法的 3 种经典题型
## 1）标准二分查找（最简单）
数组完全有序，找某个数在不在。

```
[1,3,5,7,9] 找 5 → 返回下标 2
```

## 2）旋转有序数组（你刚做的第33题）
数组被旋转过，但**局部仍然有序**。

```
[4,5,6,7,0,1,2]
```
每次判断**哪半边有序**，再缩范围。

## 3）找左边界 / 找右边界
比如找第一个大于等于 target 的位置。
嵌入式里**查找地址、查找表**经常用。

---

# 六、二分法为什么适合嵌入式Linux？
我给你说最真实的原因：

1. **超级快（O(log n)）**
   设备多、表很大时，遍历太慢。
2. **不占内存（O(1)）**
   嵌入式内存小，不能开额外空间。
3. **内核/驱动大量使用**
   - 中断向量表查找
   - 设备树匹配
   - 地址查找
   - 有序配置表
4. **面试必考**
   二分 + 链表 + 位运算 = 嵌入式三大考点

# 七、最经典例子：标准二分（一步一步跑）
数组：`[1,3,5,7,9,11,13]`
找：`7`

### 初始
left=0, right=6

### 第1次
mid=3 → nums[3]=7 → **找到了！**

**二分法 = 有序 + 每次砍一半 + 3个变量（left/right/mid）**
- 快
- 省内存
- 嵌入式必学必会
- 面试必考题
