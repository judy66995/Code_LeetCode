# 自底向上归并排序链表 —— 逐步详解

## 示例链表

```
4 -> 2 -> 1 -> 3
```

节点的内存关系（`main` 中构造）：

```
n1(4) -> n2(2) -> n3(1) -> n4(3) -> nullptr
```

---

## 一、`sortList` 主函数总览

```cpp
ListNode* sortList(ListNode* head) {
    if(!head || !head->next) return head;  // ①空链表/单节点直接返回

    // ②计算链表长度
    int n = 0;
    ListNode* p = head;
    while(p) { n++; p = p->next; }         // n = 4

    ListNode dummy(0);                     // ③哨兵节点
    dummy.next = head;

    // ④自底向上：分组长度 len 从 1 翻倍到 n
    for(int len = 1; len < n; len *= 2) {
        ListNode* pre = &dummy;            // pre 指向已排序部分的末尾
        ListNode* cur = pre->next;         // cur 指向待处理部分的起点

        while(cur) {                       // ⑤内层：遍历链表，两两合并
            ListNode* l1 = cur;
            ListNode* l2 = split(l1, len); // 切出第一组（len个节点）
            cur = split(l2, len);          // 切出第二组（len个节点），cur 指向下一组起点

            pre->next = merge(l1, l2);     // 合并两个有序组，挂到 pre 后面

            while(pre->next)               // pre 移到合并后链表的尾部
                pre = pre->next;
        }
    }
    return dummy.next;                     // ⑥返回真正的链表头
}
```

### 关键变量图解

```
dummy(哨兵) -> [已排序部分] -> [本轮待处理的剩余链表]
               ↑                ↑
              pre              cur
```

- **`dummy`**：哨兵节点，不存数据，只用于统一“在链表头插入”的操作。
- **`pre`**：每轮循环开始时指向 `dummy`。在内层处理完一组后，`pre` 移到合并结果的末尾，为下一组合并“接尾巴”做准备。
- **`cur`**：指向“还没处理的链表起点”。当 `cur == nullptr` 时，本轮所有组都处理完毕。
- **`len`**：当前每组的大小。第一轮 `len=1`（单个节点），第二轮 `len=2`，第三轮 `len=4`……直到 `len >= n`。

## 二、辅助函数详解

### `split` —— 切链表

```cpp
ListNode* split(ListNode* head, int k) {
    while(--k && head)        // 往前走 k-1 步
        head = head->next;
    if(!head) return nullptr; // 不够 k 个节点，返回空
    ListNode* next = head->next;
    head->next = nullptr;     // 断开！
    return next;              // 返回后半段的起点
}
```

**作用**：从 `head` 开始，保留前 `k` 个节点，把第 `k` 个节点的 `next` 设为 `nullptr`（断开链表），返回第 `k+1` 个节点（后半段起点）。

**细节**：`while(--k && head)` 中 `--k` 是**前置自减**。第一次进入时 `k` 已经减 1。举例 `k=2`：

| 步骤 | 进入循环前 k | 判断 `--k` | 进入循环时 k | head 走到 |
|------|-------------|-----------|-------------|----------|
| 初始 | 2 | — | — | 节点A |
| 第1次 | 2 | `--k` → k=1，条件真 | 1 | A→next = 节点B |
| 第2次 | 1 | `--k` → k=0，条件假 | — | 不进入，head停在B |

所以 `k=2` 时 while 只执行 1 次，head 停在**第2个节点**（恰好是前 k 个节点的最后一个）。

### `merge` —— 合并两个有序链表

```cpp
ListNode* merge(ListNode* l1, ListNode* l2) {
    ListNode dummy(0);                   // 局部哨兵
    ListNode* p = &dummy;
    while(l1 && l2) {                    // 两者都非空时比较
        if(l1->val < l2->val) {
            p->next = l1; l1 = l1->next; // l1 更小，接入 l1
        } else {
            p->next = l2; l2 = l2->next; // 否则接入 l2
        }
        p = p->next;                     // p 后移
    }
    p->next = l1 ? l1 : l2;              // 把剩余部分接上
    return dummy.next;
}
```

**经典双指针归并**。每次取 `l1` 和 `l2` 中较小的节点接到 `p` 后面，指针后移。最后把没走完的那条链剩余部分直接接上。

## 五、时间复杂度分析

| 轮次 | len | 内层 while 执行次数 | 每次 merge 合并节点数 |
|------|-----|-------------------|---------------------|
| 1 | 1 | 2 次 (4/2) | 最多 2 个 |
| 2 | 2 | 1 次 (4/4) | 最多 4 个 |

- 外层循环：log₂(n) = log₂(4) = **2 轮**
- 每轮遍历所有 n 个节点
- 总时间复杂度：**O(n log n)**
- 空间复杂度：**O(1)**（只用了几个指针，无递归调用栈）

## 六、关键细节问答

### Q1：为什么 `split` 中是 `while(--k && head)` 而不是 `while(k-- && head)`？

`--k` 是前置自减。`split(head, k)` 要保留前 `k` 个节点，所以 `head` 需要走到**第 k 个节点**然后断开。

假设 k=2，链表 `A -> B -> C`：

- 用 `--k`：第 1 次 `--k → 1`，head 走到 B；第 2 次 `--k → 0`，不进循环。head 停在 **B**（第 2 个）✅
- 用 `k--`：第 1 次 `k-- → 1`（但判断用旧值 2），head 走到 B；第 2 次 `k-- → 0`（判断用 1），head 走到 C。head 停在 **C**（第 3 个）❌

所以 `--k` 确保正好走 `k-1` 步，停在**第 k 个节点**。

### Q2：为什么需要 `while(pre->next) pre = pre->next;`？

merge 返回的是合并后链表的头节点，但 `pre` 需要指向**合并后链表的尾部**，这样才能在下一轮循环中把新的合并结果接到后面。所以 `pre` 要沿着链表走到末尾。

### Q3：`cur = split(l2, len)` 的作用是什么？

1. 把 `l2` 切出前 `len` 个节点作为第二组
2. 返回 `l2` 后半段的起点，赋值给 `cur`，作为**下一对要处理的组的起点**

这样 `cur` 就指向了“剩下的还没处理的链表”，当 `cur == nullptr` 时说明本轮处理完毕。

### Q4：为什么 `pre` 每轮 for 都要重置为 `&dummy`？

因为每轮 for 开始时要**重新从链表头**开始分组合并。上一轮可能已经改变了链表结构（合并后的有序组位置变了），不能从上一轮的 `pre` 位置继续。
